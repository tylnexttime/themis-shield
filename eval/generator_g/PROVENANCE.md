## Model settings (and why)

Alibaba Model Studio, OpenAI-compatible chat completions, streamed with `stream_options.include_usage`, at most 4 requests in flight per model. Token guards in `ali.py` (2,000,000 per model, 8,000,000 in total, read from `usage.jsonl` before every request). The probe findings below are measurements, not opinions:

- tiny probe (one request per code, a few tokens): all six assigned codes accepted by POST /chat/completions (HTTP 200). kimi-k3.1-pro is NOT in the GET /models list (101 models listed; the other eight codes used or named as substitutes are listed) but chat completions accepted it, so no substitution was made for it.
- kimi-k3 settings: a non-default temperature is rejected (HTTP 400 invalid_parameter_error: temperature=0.7 not supported), so no temperature is sent. enable_thinking=false is honoured. Thinking on, one probe document: 8,000 completion tokens, all reasoning, no output (max_tokens reached) -> thinking off. Thinking off: 480-602 completion tokens per 1.2-1.9K-character probe document, about 4.4K prompt tokens.
- qwen3.8-max-0902 settings: enable_thinking=false honoured. Thinking on, one probe document: 28,263 completion tokens (27,591 reasoning), 628 s, against 364-631 completion tokens and 10-18 s with thinking off -> thinking off.
- glm-5.3 settings: enable_thinking cannot be switched off (HTTP 400: the value is restricted to True). thinking_budget is ignored (519 vs 535 reasoning tokens for one trivial prompt with and without budget 100); reasoning_effort=low gave 0 reasoning tokens on that prompt (535 at the default) and 98-811 reasoning tokens on probe documents (377 on average over the 99 documents of the author round) -> reasoning_effort low, thinking switch left at the model default.
- labellers: deepseek-v4-pro-0813, kimi-k3.1-pro and deepseek-v4.1-flash-1017 follow the markup (probe: 0 markup errors, 10-14 of 11-16 gold spans matched exactly on the probe text); enable_thinking=false honoured; temperature 0.
- max_tokens: all six codes accept max_tokens up to 32,000 (probe at 16,000 and 32,000).
- author probes (two throwaway specifications per author, ids PROBE-<half>-1/2, kept in probe/): all three authors followed the markup and returned only the document (0 parse errors). glm-5.3 returned one personal probe document without any gold marker (rule P_PI); one prompt revision was made (a reminder line in the user message; Japanese names asked in kana, because the validator's Japanese detector looks for kana) and glm-5.3 then followed the markup on both probe specifications. No substitution for an author was needed.
- prefix caching: implicit: cached_tokens is 0 on the first request and about 3,000-4,000 from the second request with the same system prompt on; about 80% of the prompt tokens of the author round were cached.
- system prompt size: author system prompt = compact brief + compact taxonomy + minified profile: about 5.55K prompt tokens per author request on average (user specification included; aimed under 5K, not reached). Repair requests carry the brief only, review requests the marker protocol part of the brief plus the compact taxonomy.

## Notes

- Every earlier split came from template generators or one Claude model; split G is per-document prose by non-Claude model families, one family per role, so document style differs by half.
- Pointer check v2 (half R only): the first pass of half R's labeller with the original prompt flagged 68 of 98 documents, with reasons that treated invented personal names as real public figures. The prompt was re-run once with the same question plus the clarification that all private persons are invented (names that merely sound real are not a flag) and `when in doubt, false`; on a 15-document probe (10 of the v1 flags, 3 unflagged, 2 synthetic documents naming real companies and a famous person next to invented-person misconduct) it flagged the 2 synthetic positives only. The v1 results are kept in `results/r/pointer-v1/`. Halves S and T kept the original prompt (first-pass flag rates in `rounds/`).
- Author prompt revision (one, as allowed): after the glm-5.3 probe produced a personal document with no gold markers, the user message got a reminder to wrap every personal item, and the Japanese `names` instruction asks for kana (the validator's Japanese detector looks for kana).
- The workplace `organisation` field of non-profiled cases carries the plan's label (workplace number and sector); the invented workplace's own name appears only in the prose.
- Rounds (counts) are in `halves/<x>/rounds/`; token numbers per phase are in `usage-summary.md`.
